# Stamp Shift launch form

Only `/apps/stamp-shift` loads the waitlist and optional landing-motion scripts. Its isolated `StampShiftLanding.astro` shell follows the [scoped design contract](stamp-shift-landing-DESIGN.md): sage/ivory, local Baloo 2, real native game imagery, a visual Stash/Flip/Send strip and one launch form. The directory, support and privacy retain their static editorial shell and addresses. The game page has no portfolio navigation or chat widget. The copy/layout audit found no feature-tile grid, invented metrics, repeated headings or owner-name promotion.

`PUBLIC_WAITLIST_API_URL` must be an explicitly configured HTTPS URL ending `/api/studio/waitlist`, without credentials, query or fragment. Missing configuration yields an honest closed-notifications state and contact email. No fallback endpoint or pretend save exists. No JavaScript yields disabled controls and a contact link. Support/privacy addresses remain stable.

The form requires an email; pressing **Notify me** is the explicit per-app launch-notification request. A valid submission sends `consent: true` with consent version `launch-v1`, hides an abuse honeypot, disables while saving, validates server success, and keeps entries for retry on network/storage failure. The API contract/runbook lives in the Chicks repository's `docs/studio-waitlist.md`. No sender is configured; no confirmation email is claimed. Manual per-app withdrawal and private cross-app matching are disclosed in privacy. A `?source=` value is mapped only to `direct`, `organic`, `meta-planning` or `meta-drawer`; arbitrary UTM/referrer values are discarded. First-party signup source counts do not claim installs or purchases. No pixel/SDK or tracking cookie is added.

The original native image is copied unchanged from Stamp Shift `build/evidence/isometric-2026-10-27/pro-screens/5290BC65-EE5D-4BEE-B919-3C285E19DF99.png`: October 27, 2026, Route 4 Morning Collection at zero moves, SHA-256 `13623163aea17fbcd8133f28774e6b3ec7c755d9ba1420f9aad46f5feeeab372`. Astro produces a WebP fallback when the current poster is absent. Current media lives in `public/assets/stamp-shift/`; provenance, source hashes, device license and the9.5-credit generation ledger are tracked in [the media manifest](stamp-shift-landing-media.json). The video is labeled **Gameplay preview** and uses a continuous14.3-second Route4 recording at1×, followed by a0.7-second held ending, composited into a licensed real iPhone frame. Some small action icons predate the latest cosmetic polish; gameplay and vocabulary match. Generated scenery is decorative and never substitutes for native gameplay. Actual App Store files/candidate were not edited.

`stamp-shift-motion.ts` loads each video source only when visible and plays it muted on a loop. Hidden tabs and offscreen media pause. Reduced motion and Save-Data keep the static posters without loading video. Autoplay refusal and individual media failures leave that video's poster without stopping the remaining motion. There is no visible pause/play control. No JavaScript preserves the product image and support contact path. Missing optional assets are omitted during the static build. No framework or animation dependency was added.

Local browser fixtures use `astro build --mode test` plus the explicit `http://127.0.0.1:4334/api/studio/waitlist` fixture endpoint. HTTP localhost is rejected in normal builds. The fixture counts only synthetic requests and cannot send mail or contact a live database. Screenshots and browser tests demonstrate client behavior only; real Vercel/KV/Neon origin/storage validation remains a deployment gate.

The existing deploy workflow supplies the nonsecret repository variable `PUBLIC_WAITLIST_API_URL` to **both** test and deployment builds. Leave it absent until the API, restricted role, migration and real-origin journey are approved and verified. Adding this variable enables the form in the next build; removing it and rebuilding closes notifications. Existing self-hosted runner routing is unchanged.


Prior form verification (before the independent game landing): website unit tests 93/93; default Playwright caller 73/73; isolated waitlist fixture 3/3 (desktop/mobile invalid, consent, duplicate, success/failure and no JavaScript). `tsc --noEmit` passes. A pre-existing reduced-motion test option was placed under Playwright `contextOptions`, preserving its behavior and fixing its old type error with the warm installed runtime. The fixture suite is ignored by the default config and explicitly run in CI with its own two local servers; the default E2E rebuild also receives the repository API URL variable. The unset-URL build was exercised in a real browser at 1280/390px: no form, clear closed-notifications state and working contact email, with no console/page errors. Fixture runs produce only the expected synthetic HTTP 503 console error; no page exceptions. All task-owned ports 4321/4333/4334/4335 are stopped after checks. The DESIGN front matter/token values were preserved; the optional Google DESIGN linter is not installed and no packages were installed.

Landing checks cover visible/offscreen/hidden motion lifecycle, reduced motion, Save-Data, isolated failures and autoplay rejection without retry loops. The form fixture rejects any request without app-scoped `consent: true`, `launch-v1`, an empty honeypot and no cookie; browser coverage exercises native invalid state, success, duplicate normalization and failure retry. The fetch still omits credentials, times out after10 seconds and preserves the entered email after an error. Real deployment-origin and storage validation, the locked self-hosted CI and required GitHub approval remain publication gates.
