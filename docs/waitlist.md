# Stamp Shift launch form

Only `/apps/stamp-shift` loads the small waitlist script. The directory, support and privacy pages remain static. Existing paper/ink, Switzer/Chillax and editorial layout stay intact; the overview is a Decide/Learn surface. The design reference is the current product; the installed Figma template informed only restrained chrome with colorful product content. No layout/font cloning. Anti-slop audit: 0/10 tells; no decorative headings, cards, metrics or animation added.

`PUBLIC_WAITLIST_API_URL` must be an explicitly configured HTTPS URL ending `/api/studio/waitlist`, without credentials, query or fragment. Missing configuration yields an honest closed-notifications state and contact email. No fallback endpoint or pretend save exists. No JavaScript yields disabled controls and a contact link. Support/privacy addresses remain stable.

The form requires an email and unchecked per-app consent, hides an abuse honeypot, disables while saving, validates server success, and keeps entries for retry on network/storage failure. The API contract/runbook lives in the Chicks repository's `docs/studio-waitlist.md`. No sender is configured; no confirmation email is claimed. Manual per-app withdrawal and private cross-app matching are disclosed in privacy. A `?source=` value is mapped only to `direct`, `organic`, `meta-planning` or `meta-drawer`; arbitrary UTM/referrer values are discarded. First-party signup source counts do not claim installs or purchases. No pixel/SDK or tracking cookie is added.

The native image is copied unchanged from Stamp Shift `build/evidence/isometric-2026-10-27/pro-screens/5290BC65-EE5D-4BEE-B919-3C285E19DF99.png`: October 27, 2026, Route 4 Morning Collection at zero moves, SHA-256 `13623163aea17fbcd8133f28774e6b3ec7c755d9ba1420f9aad46f5feeeab372`. It is labeled Development preview; Astro produces responsive WebP derivatives. Actual App Store files/candidate were not edited.

Local browser fixtures use `astro build --mode test` plus the explicit `http://127.0.0.1:4334/api/studio/waitlist` fixture endpoint. HTTP localhost is rejected in normal builds. The fixture counts only synthetic requests and cannot send mail or contact a live database. Screenshots and browser tests demonstrate client behavior only; real Vercel/KV/Neon origin/storage validation remains a deployment gate.

The existing deploy workflow supplies the nonsecret repository variable `PUBLIC_WAITLIST_API_URL` to **both** test and deployment builds. Leave it absent until the API, restricted role, migration and real-origin journey are approved and verified. Adding this variable enables the form in the next build; removing it and rebuilding closes notifications. Existing self-hosted runner routing is unchanged.
